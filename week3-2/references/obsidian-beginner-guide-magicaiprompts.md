## Why This Is Useful For Week 3

This article gives a beginner-friendly sequence for explaining Obsidian:

1. What Obsidian is
2. Why Markdown/local files matter
3. How to install it
4. How to create a Vault
5. How to write the first note
6. How to connect notes with `[[wikilinks]]`
7. How to use Graph View
8. How to expand with MOC, daily notes, plugins, templates, and search

This matches the workshop story:

> AI conversations are useful, but they disappear into chat history unless we save and organize them. Obsidian gives us a local Markdown knowledge base where those answers can be stored, linked, searched, and reused.

## Key Points To Reflect In Slides

### 1. Obsidian Definition

Obsidian can be introduced as:

- a local Markdown note app
- a personal knowledge management tool
- a way to connect notes using links and backlinks
- a graph-based view of your own knowledge structure

Workshop phrasing:

> Obsidian is not just a memo app. It is a folder of Markdown notes that can be linked into a personal knowledge base.

### 2. Core Beginner Flow

Use this order for the first 20 minutes:

1. Install Obsidian from `obsidian.md`
2. Create a Vault
3. Make the first note
4. Write in Markdown
5. Link notes with `[[note name]]`
6. Open Graph View

This is a good pacing buffer before moving into Claude Code and AI knowledge-base workflows.

### 3. Vault Explanation

Beginner-friendly framing:

- A Vault is just a folder.
- Notes are `.md` files.
- Existing Markdown folders can be opened as Vaults.
- Use simple names and locations like Desktop or Documents for workshop practice.

Workshop phrasing:

> Vault sounds technical, but it just means "the folder where my notes live."

### 4. First Note Demo

Suggested first note:

```md
# ChatGPT에서 배운 것

## 오늘 얻은 답변

- AI 답변은 대화창에만 두면 찾기 어렵다.
- 중요한 답변은 노트로 저장해야 한다.
- 관련 개념은 링크로 연결해야 한다.

## 연결할 개념

- [[AI 대화 기록]]
- [[개인 지식베이스]]
- [[Obsidian Graph View]]
```

### 5. Wikilink Demo

The article highlights `[[노트제목]]` style linking.

Workshop demo:

1. Type `[[개인 지식베이스]]`
2. Click the link
3. Create the new note
4. Go back and show the link connection

### 6. Graph View Demo

Graph View should be explained as:

- nodes = notes
- lines = links
- center nodes = frequently linked hub notes
- isolated nodes = notes that are not yet connected

Workshop phrasing:

> Graph View is not just a pretty visualization. It shows whether your knowledge is connected or scattered.

### 7. MOC

The article recommends MOC, Maps of Content.

For this workshop, explain MOC as:

- a table-of-contents note
- a hub note for one topic
- a way to make Graph View meaningful

Examples:

- `AI 학습 MOC`
- `논문 리뷰 MOC`
- `프로젝트 MOC`

### 8. Daily Notes

Daily Notes are useful but optional for this lecture.

Use them as a short mention:

> Daily Notes are good for logging what you learned today. Later, important parts can be moved into topic notes.

### 9. Beginner Warnings

Important points from the guide:

- Do not install too many plugins at first.
- Do not try to design a perfect system from day one.
- Build the habit of writing notes first.

Workshop phrasing:

> The goal today is not to build the perfect second brain. The goal is to stop useful AI answers from disappearing.
