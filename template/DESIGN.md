# 슬라이드 디자인 원칙

이 워크샵 슬라이드를 만들거나 고칠 때 지키는 규칙입니다. 청중이 **비개발자(교수님 · 조교) · 발표장 뒷줄에서도 읽혀야 하는** 상황이 기준입니다.

## 큰 원칙 하나

한 슬라이드 = **사진 하나 + 큰 글씨 1~3줄**. 나머지는 다 잘라내세요.

## 하지 말 것

- **회색 배경 카드 반복 금지** — `background: var(--bg-elev)` 로 padding 채운 박스가 3개 이상 나열되면 정보 밀도만 높고 뒷줄 청중은 못 읽습니다. 카드로 정리하고 싶어지면 = 슬라이드 두 개로 쪼개세요.
- **작은 회색 각주 금지** — `--small-size` + `--muted` 로 붙인 "* 이거 참고" 는 발표장에서 안 읽힙니다. 진짜 중요하면 본문으로, 아니면 삭제.
- **한 슬라이드에 리스트 4개 이상 금지** — 3개까지가 인지 상한. 넘으면 새 슬라이드.
- **이런 톤 금지**: 명사 끊기 · 도치 · 대시(—) 대구식. 자연스러운 `~합니다` 종결로.
- **AI 슬롭 톤 예시**: "이름만 다르고 하는 일은 같습니다 — 검은 화면에 명령어를 적어 컴퓨터를 조작합니다." → "명령어를 입력해 컴퓨터를 조작하는 프로그램입니다."

## 할 것

- **글자 크게** — 본문 최소 `clamp(0.95rem, 1.5vw, 1.4rem)`. 핵심 문장은 `clamp(1.15rem, 2.4vw, 2rem)` 까지 올려도 좋습니다.
- **사진 좌 · 문장 우** — `grid-template-columns: minmax(0, 1.5fr) minmax(0, 1fr)` 정도. 사진이 크게, 옆에 짧은 문장만.
- **강조는 색으로만** — 키워드 하나에 `color: var(--accent); font-weight: 700`. 배경 채우기 X.
- **테두리만** — 사진에 `border: 1px solid var(--line-2); border-radius: 8px; overflow: hidden;` 이 정도.
- **STEP 라벨은 위에** — 사진 위에 `STEP 1 — claude 입력 후 Enter` 형태 라벨. 카드 안에 감싸지 말 것.

## 예외

이런 상황에서만 어두운 배경 / 카드 형식 OK:

- **터미널 목업** — 실제 실행 화면을 코드로 흉내 낼 때. `background: #1A2230` + monospace.
- **프롬프트 박스** — 청중이 복사해서 붙여넣을 프롬프트. `background: var(--accent-soft); border-left: 3px solid var(--accent);` 로 시각적 구분. 프롬프트 문장은 `>` 로 시작.
- **워크플로우 다이어그램** — STEP 1 → STEP 2 → STEP 3 흐름 표시. flexbox 화살표로 연결.
- **시나리오 4장 카드** (예: STRUCTURE / EXTRACT / COMPARE / VALIDATE) — 예제 시작 시 미리보기 성격의 대비. 4개 이하.

## 색 · 폰트 · 토큰

`template/foundation.css` 참고. 자주 쓰는 것:

- `var(--bg)` 배경 (크림 화이트)
- `var(--ink)` / `var(--ink-2)` 본문 잉크
- `var(--accent)` 옥스퍼드 블루 (강조 · 링크 · 프롬프트 왼쪽 선)
- `var(--term-green)` 초록 (STEP 3 · 완료 상태)
- `var(--warn)` / `var(--warn-soft)` 주황 (주의 · 스캔본 안내)
- 폰트: **Pretendard** (한글 본문), **JetBrains Mono** (코드 · 라벨)
