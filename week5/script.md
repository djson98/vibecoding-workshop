## 01. 표지 · 1분

오늘은 Claude Code가 내 컴퓨터 안의 파일만 읽는 단계를 넘어, Google Drive 같은 외부 업무도구를 읽게 만드는 방법을 다룹니다.

연결 자체보다 더 중요한 것은 연결한 뒤의 작업 순서입니다. 외부 자료를 읽고, 데이터의 오류를 점검하고, 결과와 근거를 Obsidian에 남기는 흐름을 끝까지 만들어보겠습니다.

## 02. 오늘 할 것 · 2분

수업은 네 부분입니다.

먼저 MCP가 무엇인지 20분 정도 이해합니다. 그 다음 지원 Connector 또는 MCP 서버를 실제로 연결합니다. 가장 긴 실습에서는 Drive와 Sheets 자료를 점검해 Obsidian 노트로 만듭니다. 마지막에는 서로 결과를 보고, 다음에 자동화할 업무를 하나 정합니다.

연결이 안 되어도 수업은 멈추지 않습니다. 5분 이상 막히면 준비된 로컬 샘플로 같은 실습을 진행하고 쉬는 시간에 연결 문제를 해결하겠습니다.

## 03. 수업이 끝나면 이것이 남습니다 · 2분

오늘의 결과물은 멋진 채팅 답변이 아닙니다. Obsidian에 저장된 업무 노트 한 장입니다.

이 노트에는 자료 출처, 핵심 수치, 문제가 있는 행의 근거, 다음 행동이 들어갑니다. 한 달 뒤에 다시 열어도 무엇을 보고 어떤 판단을 했는지 이해할 수 있어야 합니다.

## 04. 먼저 경계를 구분합니다 · 3분

Obsidian Vault처럼 내 컴퓨터에 있는 폴더는 Claude Code를 그 폴더에서 실행하면 읽을 수 있습니다. 이를 위해 MCP를 따로 설치할 필요는 없습니다.

반면 Drive, Gmail, Slack, Notion은 내 컴퓨터 밖의 서비스입니다. 로그인과 접근 권한이 필요하기 때문에 Connector 또는 MCP가 필요합니다.

오늘은 외부 서비스에서 자료를 읽고, 결과는 로컬 Obsidian에 쓰는 방향으로 실습합니다.

## 05. 업무자료는 한곳에 있지 않습니다 · 3분

실제 업무는 엑셀 파일 하나로 끝나지 않습니다. 요청 조건은 메일에 있고, 원본 파일은 Drive에 있고, 최신 현황은 Sheets에 있고, 왜 이 일을 하는지는 담당자의 머릿속에 있습니다.

그래서 자동화 단위를 파일 하나가 아니라 업무 흐름으로 봐야 합니다. 오늘은 그 흐름을 AI가 따라갈 수 있게 연결합니다.

## 06. MCP를 이해합니다 · 30초

먼저 용어를 짧게 정리하겠습니다. 기술 구조를 외우는 것이 아니라, 무엇을 연결하고 어떤 권한이 생기는지만 이해하면 됩니다.

## 07. MCP란? · 3분

MCP는 Model Context Protocol의 약자입니다. AI가 외부 서비스의 기능과 데이터를 일정한 방식으로 찾고 사용할 수 있게 하는 연결 규격입니다.

USB 규격을 떠올리면 쉽습니다. 기기마다 내부 구조는 다르지만 같은 규격으로 연결하면 컴퓨터가 장치를 사용할 수 있습니다. MCP도 Claude Code와 여러 업무 서비스 사이에 공통된 연결 방식을 제공합니다.

## 08. 연결에는 세 주체가 있습니다 · 3분

첫째, Claude Code는 사용자의 요청을 이해하고 어떤 도구를 쓸지 판단하는 Host입니다.

둘째, MCP 서버는 검색, 읽기, 문서 만들기 같은 기능을 도구 형태로 제공합니다.

셋째, Drive나 Notion 같은 실제 서비스가 데이터와 계정 권한을 가지고 있습니다.

Claude가 모든 서비스의 비밀번호를 직접 아는 구조가 아니라, 허용된 연결을 통해 도구를 호출하는 구조입니다.

## 09. Connector도 MCP를 쉽게 붙이는 방법입니다 · 3분

지원 목록에 있는 서비스는 Connector 화면에서 선택하고 로그인하는 방식이 가장 빠릅니다. 수업에서는 가능한 한 이 경로를 먼저 사용합니다.

지원 목록에 없거나 사내 서비스처럼 별도 연결이 필요하면 MCP 서버 주소나 실행 명령을 직접 등록합니다.

중요한 점은 인터넷에서 아무 서버나 설치하지 않는 것입니다. 서비스 공식 문서나 신뢰할 수 있는 제공자의 주소인지 먼저 확인해야 합니다.

## 10. 연결됨과 무엇이든 가능함은 다릅니다 · 3분

연결된 도구가 할 수 있는 일은 크게 읽기, 초안 만들기, 외부 상태 바꾸기로 나눌 수 있습니다.

같은 Gmail 연결이라도 메일 검색은 가능하지만 실제 발송은 지원하지 않고 초안까지만 만들 수 있습니다. 서비스와 연결 방식에 따라 기능이 다르므로, 작업 전에 사용 가능한 도구를 확인해야 합니다.

처음에는 읽기부터 시작하겠습니다.

## 11. 업무도구를 연결합니다 · 30초

이제 실제 연결 단계입니다. 경로 A와 B 중 하나만 성공하면 됩니다. 화면에 Connector가 보이는 분은 A, 터미널에서 서버를 직접 등록해야 하는 분은 B를 따라오면 됩니다.

## 12. 경로 A · 지원 Connector 연결 · 5분

Claude Desktop의 Claude Code 세션을 쓰는 경우 입력창 옆 더하기 버튼에서 Connectors를 열 수 있습니다.

Manage connectors에서 서비스를 고르고, 설명과 권한을 확인한 뒤 Connect를 누릅니다. 브라우저 로그인이 끝나면 세션으로 돌아옵니다.

연결 후 첫 요청은 업무 요청이 아니라 다음처럼 기능 확인으로 시작합니다.

```text
현재 이 세션에서 사용할 수 있는 외부 연결과 각 연결의 읽기·쓰기 기능을 알려줘.
아직 어떤 파일도 수정하지 마.
```

## 13. 경로 B · MCP 서버 직접 등록 · 5분

원격 서비스는 현재 HTTP 방식이 권장됩니다. 서비스 공식 문서에서 주소를 복사하고 `claude mcp add`로 등록합니다.

여기서 자주 틀리는 부분은 옵션의 위치입니다. `--transport`와 `--scope`는 서버 이름 앞에 둡니다. 로컬 stdio 서버는 실행 명령 앞에 `--` 구분자가 필요합니다.

슬라이드의 Notion 주소는 명령 형식을 보여주기 위한 공식 예시입니다. 오늘 Drive 실습은 지원 Connector를 우선 사용합니다.

## 14. 설정 범위는 이렇게 고릅니다 · 4분

`local`은 현재 프로젝트에서만, 나만 사용하는 설정입니다. 수업이나 시험 연결에 가장 적합합니다.

`user`는 내 모든 프로젝트에서 사용하지만 팀과 공유되지는 않습니다. 매일 쓰는 개인 업무도구에 적합합니다.

`project`는 `.mcp.json`에 기록되어 팀과 공유할 수 있습니다. 이 파일에 비밀번호나 토큰을 직접 적어 커밋하면 안 됩니다.

개인 계정이 연결되는 오늘 실습은 local을 기본으로 하겠습니다.

## 15. 등록 다음에는 인증합니다 · 4분

서버를 등록했다고 내 계정 접근이 바로 허용되는 것은 아닙니다. Claude Code 안에서 `/mcp`를 열고 인증이 필요한 서버를 선택합니다.

브라우저에서 로그인할 때 계정과 요청 권한을 확인합니다. 로그인이 끝나면 Claude Code로 돌아와 Connected 표시를 확인합니다.

브라우저 리디렉션이 실패하면 주소창의 전체 콜백 주소를 Claude Code의 입력 안내에 붙여 넣는 방식으로 마칠 수 있습니다.

## 16. 연결 확인은 세 단계로 합니다 · 3분

터미널의 `claude mcp list`는 등록된 서버 목록을 보여줍니다. `claude mcp get 이름`은 특정 서버의 설정을 확인할 때 씁니다. Claude Code 세션 안의 `/mcp`는 연결과 인증 상태를 확인하는 곳입니다.

서버 이름만 보인다고 끝난 것이 아닙니다. Connected 상태, 필요한 도구, 로그인한 계정까지 확인해야 합니다.

## 17. 안 될 때는 원인부터 나눕니다 · 3분

서버가 보이지 않으면 등록 문제입니다. 주소와 명령 순서를 확인합니다.

서버는 보이지만 로그인하라고 하면 인증 문제입니다. `/mcp`에서 다시 인증합니다.

파일이 보이지 않으면 원본 서비스에서 내 계정에 그 파일 권한이 있는지 확인합니다.

검색 결과가 없으면 폴더명, 파일명, 날짜 범위를 더 구체적으로 요청합니다.

5분 넘게 막히면 샘플 데이터로 이동합니다. 연결 성공 여부와 오늘 배울 업무 설계는 별개입니다.

## 18. 안전한 자동화 순서를 정합니다 · 30초

연결에 성공하면 Claude가 할 수 있는 일이 많아집니다. 그래서 더 분명한 작업 순서가 필요합니다.

## 19. 읽기 → 초안 → 확인 → 반영 · 4분

첫 단계에서는 목록과 구조만 읽습니다. 두 번째는 원본을 건드리지 않고 별도 초안을 만듭니다. 세 번째는 사람이 숫자와 근거를 확인합니다. 마지막에 승인한 변경만 반영합니다.

처음부터 “정리해서 다 수정해줘”라고 하면 무엇을 바꿀지 확인하기 어렵습니다. 되돌릴 수 있는 작은 단계로 나누겠습니다.

## 20. 실습은 최소 권한으로 시작합니다 · 3분

수업용 복사본을 사용하고, 개인정보나 비밀 문서는 제외합니다. 연결 권한은 읽기 중심으로 시작하고, 특정 폴더와 특정 시트만 지정합니다.

AI는 로그인한 사용자의 권한을 넘지는 못하지만, 그 사용자에게 권한이 많은 경우 접근 범위도 넓을 수 있습니다. 연결 전에 자료 범위를 좁히는 습관이 중요합니다.

## 21. 외부 문서 안의 지시문은 데이터로 취급합니다 · 3분

외부 문서에는 AI를 속이려는 문장이 들어 있을 수 있습니다. “이전 지시를 무시하라” 같은 문장을 발견해도 그것은 작업 명령이 아니라 분석할 데이터입니다.

외부 자료를 읽힐 때는 문서 안의 지시를 실행하지 말고, 요청 범위를 벗어난 도구 호출과 외부 전송을 하지 말라고 명시합니다.

## 22. Drive 자료를 업무 노트로 바꿉니다 · 30초

이제 오늘의 핵심 실습입니다. 목록화, 데이터 점검, Markdown 기록 세 단계로 진행합니다.

## 23. 실습 준비 · 3분

연결에 성공한 분은 Drive의 수업용 폴더를 고릅니다. 원본 대신 복사본을 권장합니다.

연결이 아직 안 된 분은 이 자료의 `week5/sample-data` 폴더를 사용합니다. Claude Code를 워크숍 폴더에서 실행하면 로컬 파일을 바로 읽을 수 있습니다.

결과는 Obsidian Vault의 `40_Work/2026-업무자동화` 폴더에 저장합니다. Vault가 없는 분은 우선 현재 폴더에 결과를 만들고 나중에 옮겨도 됩니다.

## 24. 1단계 · 먼저 목록만 봅니다 · 5분

첫 프롬프트는 파일 내용을 전부 분석하는 요청이 아닙니다. 폴더 안에 무엇이 있고 어떤 파일이 관련 있어 보이는지 확인하는 요청입니다.

마지막에 어떤 도구를 사용했고 무엇을 읽었는지 적게 하면 연결이 실제로 사용됐는지 확인하기 쉽습니다.

결과에서 내가 의도한 폴더와 파일이 보이면 다음 단계로 넘어갑니다.

## 25. 2단계 · Sheets를 점검합니다 · 8분

시트 구조를 확인한 다음 누락, 중복, 상태 이상값을 검사합니다.

여기서 “이상값을 찾아줘”만 요청하지 않고 판단 기준을 명시합니다. 이메일 기준 중복, 제출 또는 미제출 외의 상태, 마감이 지났는데 미제출인 사람처럼 기준을 씁니다.

결과는 요약 수치와 문제가 있는 행의 근거를 나눠 받습니다.

오프라인 샘플의 예상 확인 항목은 다음과 같습니다.

- 이메일 누락 1건
- 이메일 중복 1쌍
- 제출상태 표기 이상 1건
- 마감 후 미제출 대상 존재

정답을 맞히는 것보다, 어떤 규칙으로 그렇게 판단했는지 확인하는 것이 중요합니다.

## 26. 3단계 · 숫자를 검산합니다 · 5분

전체 행 수가 정상 행과 확인 필요 행의 합과 맞는지 봅니다. 제출 대상 수가 제출과 미제출의 합과 맞는지도 확인합니다.

AI가 만든 요약 수치 하나를 골라 원본에서 직접 세어봅니다. 자동화 결과를 믿는다는 것은 검증을 생략한다는 뜻이 아닙니다. 검증하기 쉬운 형태로 결과를 받는다는 뜻입니다.

## 27. 4단계 · Obsidian 업무 노트로 남깁니다 · 4분

업무 노트에는 요청 정보, 원본 자료, 요약, 점검 결과, 다음 행동, 생성 기록을 남깁니다.

특히 원본 파일과 시트 이름이 있어야 나중에 숫자를 다시 확인할 수 있습니다. 생성 기록에는 사용한 도구와 원본 수정 여부를 적습니다.

## 28. 한 번에 요청할 때는 계약처럼 씁니다 · 5분

익숙해지면 전체 작업을 한 프롬프트로 요청할 수 있습니다. 이때는 목적만 쓰지 말고 입력, 작업 순서, 결과 경로, 제약 조건을 함께 씁니다.

작업 전에 생성 경로와 목차를 먼저 보여달라고 하면 잘못된 위치에 파일을 만드는 실수를 줄일 수 있습니다.

불확실한 값을 추측하지 않고 확인 필요로 표시하게 하는 문장도 중요합니다.

## 29. 선택 실습 · Gmail 요청까지 연결하기 · 6분

시간이 남고 Gmail 연결이 된 분은 업무의 앞단까지 확장합니다.

관련 요청 메일을 찾아 마감일과 처리 조건을 추출합니다. Drive 자료를 점검하고 Obsidian에 기록한 뒤, 답장 초안을 만듭니다.

수신자, 숫자, 첨부, 민감정보는 사람이 확인하고 직접 전송합니다. 오늘은 자동 발송이 목표가 아닙니다.

복사용 프롬프트:

```text
최근 30일 메일에서 제목에 {업무명}이 포함된 요청 메일을 찾아줘.

1. 요청자, 요청일, 마감일, 해야 할 일을 추출해줘.
2. 연결된 Drive 자료가 있으면 파일명만 먼저 알려줘.
3. 오늘 만든 점검 노트를 참고해 처리 결과 답장 초안을 작성해줘.

메일은 보내지 말고 초안만 보여줘.
수신자, 숫자, 첨부파일은 확인 필요 항목으로 따로 표시해줘.
```

## 30. 종합 실습 · 30분

이제 각자 업무자료 하나를 선택해 검증 가능한 업무 노트로 바꿉니다.

처음 5분에는 무엇을 입력으로 쓰고 어떤 노트가 나오면 완료인지 정합니다. 다음 10분에는 목록과 구조와 이상값을 확인합니다. 그 다음 10분에는 Markdown 노트를 만듭니다. 마지막 5분에는 요약 수치 하나를 원본에서 직접 검산합니다.

완성 기준은 예쁜 요약이 아니라 출처와 다음 행동이 보이는 노트입니다.

## 31. 제출 전 6개만 확인합니다 · 4분

옆 사람과 노트를 바꿔 여섯 항목을 확인합니다.

원본 파일과 시트명이 있는지, 수치 합계가 맞는지, 문제 행을 다시 찾을 근거가 있는지 봅니다. 추측과 사실이 구분되어 있고, 원본을 임의로 수정하지 않았으며, 다음 행동이 보이면 완료입니다.

## 32. 오늘의 정리 · 3분

오늘은 자료가 있는 곳에 연결하고, 근거와 숫자를 확인하고, 업무 맥락을 Obsidian에 남겼습니다.

MCP의 핵심은 연결의 개수가 아닙니다. 반복해서 복사하고 붙여 넣던 업무 흐름 하나를 안전하고 검증 가능한 형태로 바꾸는 것입니다.

AI가 자료를 찾고 초안을 만들게 하되, 사람은 범위와 기준과 최종 행동을 결정합니다.

다음 시간 전까지 내가 반복하는 업무 하나를 골라 입력, 판단 기준, 결과물 세 가지를 적어보세요. 그것이 다음 자동화의 설계도가 됩니다.

## 질문을 받았을 때 짧은 답변

### MCP가 없으면 Claude Code가 Obsidian을 못 읽나요?

아닙니다. Obsidian Vault는 로컬 폴더이므로 Claude Code를 해당 폴더에서 실행하면 읽을 수 있습니다. Drive나 Notion처럼 외부 서비스에 접근할 때 Connector 또는 MCP가 필요합니다.

### Connector와 MCP 중 무엇을 써야 하나요?

지원 목록에 있고 기능이 충분하면 Connector가 쉽습니다. 목록에 없거나 사내 도구처럼 맞춤 연결이 필요하면 MCP 서버를 직접 등록합니다.

### Project 범위가 더 안전한가요?

아닙니다. Project는 팀 공유를 위한 범위입니다. 개인 계정과 자격 증명이 관련된 실습은 local 또는 user 범위를 씁니다. 공유 설정에는 비밀값을 직접 넣지 않습니다.

### AI가 Gmail에서 바로 메일을 보내나요?

현재 Google Workspace 연결에서는 Gmail을 검색하고 읽고 초안을 만들 수 있지만, 전송은 사람이 Gmail에서 직접 합니다. 수업에서도 초안까지만 만듭니다.

### Drive의 이미지도 분석하나요?

연결 기능에 따라 다릅니다. Google Drive 연결은 문서에서 텍스트를 추출하며, 문서 안에 삽입된 이미지는 처리되지 않을 수 있습니다. 이미지 분석이 필요하면 파일을 별도로 제공하고 결과를 확인합니다.
